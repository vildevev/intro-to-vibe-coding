Coding Interview Patterns — 401

Mission. Sixteen patterns drilled to recognition speed: cues, templates you can rebuild under pressure, and a mock interviewer for every one.

A senior-engineer track: the 16 patterns behind nearly every coding interview question, drilled to recognition speed.

Who this is for: engineers facing leetcode-style interviews (and senior loops, where coding is still the gate). Not a "grind 500 problems" course — the insight it's built on is that interview questions are instances of a small number of patterns, and the skill being tested is recognition speed: seeing the problem, naming the pattern, executing the template.

How it works: 10 challenges covering all 16 patterns (related patterns are paired). Each challenge gives you the recognition cues, a template you can rebuild from memory, complexity bounds, and drills — including a copy-paste prompt that turns any AI chat into a mock interviewer that picks the problem, enforces time, and hints only when you're stuck.

Source note: the pattern taxonomy follows the same arc as Hello Interview's coding material — original explanations here; use their site for worked video solutions.

The Interview Rules

  1. Recognition first. 80% of the battle is the first 60 seconds: restate the problem, spot the pattern, say it out loud before you write anything.
  2. Templates, not memorized solutions. For each pattern you own one skeleton you can rebuild under pressure — problems are variations; the skeleton is constant.
  3. Complexity is part of the answer. Every solution gets its time/space stated unprompted, with the "why."
  4. Think out loud, always. Silence reads as being stuck. Narrate the brute force, then improve it — a verbal brute force is a passing answer; silent genius is unreadable and rare.
  5. Tests are free points. Trace a small example before saying "done." Interviewers weigh the check as a senior signal.

Before you start

  • An AI chat for mock interviews (any strong model works)
  • A language you'll interview in, picked once and kept (usually the one you know best, not the trendiest)
  • A plain editor or CoderPad-style scratchpad — no autocomplete during drills

FAQ

Senior loops too? Yes — senior coding rounds ask the same patterns with more ambiguity and higher expectations on communication and edge cases. The drills here lean senior: state assumptions, handle edges, narrate trade-offs.

How many problems total? The drills reference ~40 classic problems by name. That's deliberately small: 40 problems owned (pattern named, template reproduced, complexity stated, edges handled) beat 500 skimmed.

Order matters? Mostly. DP last on purpose — it's the pattern that pays off from everything before it.
